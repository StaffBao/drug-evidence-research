# 呈现与迭代

要把研究做成报告、幻灯片、表格、机制图或更新既有成品时读取。遵循用户选择的格式；只在需要实际制作时使用当前环境可用的对应制作工具。

## 易懂来自结构与解释

先说结论及适用范围，然后给支持它的比较。不要为了短把药物、剂量、对照或估计口径省掉。缩写首次展开，统计术语旁用一句话说明它回答什么问题。

数值有对应关系就用表：

- 多剂量：一行一个剂量，结果与安全性使用同一组别 ID。
- 多臂：先设计表，再疗效表和安全性表；很多指标时分视图，保留总览入口。
- 跨国家或地区：一行一个用途和产品；可切换地区，但空白状态要解释。
- 生理机制：来源细胞 → 分子与受体 → 靶细胞或器官 → 生理作用；药物干预另标清楚。

避免“其余相近”“效果更好”“未达非劣”“二联、三联”等没有完整对象的孤立结论。写成“哪几个组、哪个结局、哪个时点、相对哪个对照、数值或不确定性是什么”。如果原文只有有限比较，说明未逐组报告，不能补齐假数据。

## 图表的语义

颜色可区分疾病、产品或机制；证据状态另外用文字或纹理编码。一个次要终点或某剂量未达成，不要给整页套“失败”色。日期精度和预计状态使用不同符号，并保留图例。图形接近、数值大小或箭头方向均不能代替统计判定。

数字旁放时点、分母、单位和简短来源；详细限制可放脚注或点击说明，关键限制仍留在主页面。交互说明要能用键盘打开和关闭。静态导出也应保留关键身份、数据与限制，不依赖只能悬停看见的信息。

## 更新现有研究成品

1. 读取真实数据源和构建流程，区分用户手工排序与生成器默认顺序。
2. 用稳定 ID 定位主张、组别和页面，避免按会变化的页码硬编码。
3. 修改原始结构化数据或编辑源，再生成成品；核查是否有其他正文、表格、弹窗或术语说明重复同一主张。
4. 章节合并或改名时检查目录、章节号、页脚、筛选器、前后过渡和引用链接；不顺手改动无关章节。
5. 可交互 HTML 改动后检查屏幕适配、滚动、按钮、跳转、导出和重开。对有本地编辑缓存的页面，验证旧缓存不会覆盖新结构，同时保留用户已有编辑。

不强制某个固定画布、框架或视觉风格。采用现有作品的布局约定；内容放不下优先拆分或加可点击细节，不缩小到难以阅读。

## 交付前用读者的眼睛检查

抽查最容易看错的表：组别和结果对应、两个药物各自剂量、主要与延长时点、人数与次数、SAE 与重度、已批准与计划。对照原表核实关键数值和链接，检查排版后限制语是否消失。

交付时说明改了什么、依据是什么、验证了什么以及仍存的实质缺口。不要把“链接能打开”当作完成内容核查，也不要把格式检查称为科学结论通过验证。
